# Передача проекта в VS Code

## Контекст команды

Команда делает учебный блэкджек с улучшениями и короткими забегами в духе Balatro. Пользователь попросил совместить 2D и 3D и подготовить архитектуру для дальнейшей работы с Codex в VS Code. Выбран вариант: 3D-стол, карты и фишки плюс 2D-интерфейс.

На скриншоте курса прямо требуется OpenGL с современным шейдерным конвейером, сцена, преобразования, хотя бы одна техника освещения/шейдинга и текстуры либо аналогичный эффект. Язык на скриншоте не указан; для реализации выбран C++17. Раннее предложение использовать Godot заменено этим стеком после получения задания. Подробное соответствие — в [COURSE_REQUIREMENTS.md](COURSE_REQUIREMENTS.md).

Это стартовый играбельный прототип. Финальный отчёт по шаблону, презентация, видео и проверка на машине TA ещё остаются задачами команды. Шаблон отчёта и полная рубрика не предоставлены.

## Запуск рабочего окружения

1. Установите компилятор и CMake по README. Для Windows нужны MSVC и Windows SDK из Visual Studio/Build Tools; расширение редактора их не заменяет.
2. Клонируйте `https://github.com/F1j1tun1/Final-Project-CGF.git`. В VS Code выберите **File → Open Folder** и откройте корень `Final-Project-CGF`.
3. Установите расширения Microsoft **C/C++** и **CMake Tools**. Выберите configure preset `desktop`, затем цель запуска `blackjack_forge`.
4. Установите официальное расширение Codex, откройте его боковую панель и выполните предлагаемый вход. Актуальный порядок установки и входа описан в [официальной документации OpenAI — Codex IDE extension](https://developers.openai.com/codex/ide/).
5. Во встроенном терминале проверьте проект:

```text
cmake --preset desktop
cmake --build --preset desktop --parallel
ctest --preset desktop
```

На Windows с генератором Visual Studio запустите:

```powershell
.\build\desktop\Debug\blackjack_forge.exe --demo --seed 42
```

Для Linux команды системных пакетов и отключение Wayland при необходимости приведены в README. При отсутствии графической сессии используйте `core-only`: это позволит работать над правилами, но не подтвердит работу рендерера.

Файлы передачи сохраняют контекст независимо от доступности истории чата. Открытие этой папки само по себе не означает автоматический перенос текущей беседы в расширение: начните запрос с инструкции прочитать документы проекта.

## Контракт модулей

`Game` принимает команды `deal`, `hit`, `stand`, `advance`, `buy`, `leaveShop`, `restart` и отдаёт `const Snapshot&` через `state()`. Недопустимые действия возвращают `false` без изменения состояния. `Snapshot` содержит игровую информацию, но не позиции карт и не время анимации. Не изменяйте состояние обходным путём из UI.

Приложение читает Snapshot и создаёт `gfx::Scene`: визуальные карты, фишки и время. Пока идёт ход игрока, вторая карта дилера закрыта. `Renderer` получает Scene и `RenderSettings`, рисует объекты и не считает победителя или награды. OpenGL-ресурсы создаются и уничтожаются при живом контексте.

Сохраняйте воспроизводимость по seed. Игровой модуль не должен зависеть от ImGui, GLFW, OpenGL, реального времени или длительности кадра. Визуальные задержки не должны менять порядок карт, вероятность исходов или начисление очков.

Начальный баланс зафиксирован в архитектуре: цели 30/65/100, пять раздач на этап, четыре улучшения по 3 монеты, награда этапа 5 монет. Ничья сохраняет серию побед; серия переносится между этапами; Second Chance обновляется на новом этапе. Проверка достижения цели имеет приоритет над исчерпанием раздач.

## Текущий статус проверки

Проверено 15 октября 2026 на Windows: Debug/Release собраны MSVC 19.51 и CMake 4.4.3; CTest Release прошёл 3 000 забегов и 1 147 808 проверок без ошибок. Intel OpenGL 3.3 выполнил графический прогон из 600 кадров с магазином и победой на третьем этапе; проверены PNG-кадры стола, магазина и финала. См. [VERIFICATION.md](VERIFICATION.md). При продолжении повторите проверки в своём окружении; Linux/macOS и машина TA ещё не проверены.

Для графики используйте `--smoke` и кадр `--hidden --demo --frames 3 --screenshot preview.png`. Даже скрытому окну нужны графическая сессия и OpenGL. После этого вручную проверьте интерфейс, раздачу, магазин, финал и изменение размеров окна. Сборка на второй машине и на компьютере TA пока остаётся отдельной задачей.

## Следующие задачи

1. **Анимация раздачи и переворота.** Добавить события презентации и стабильные идентификаторы карт. Новые карты движутся от колоды к месту руки; закрытая карта дилера переворачивается при раскрытии. Переход к следующей раздаче и restart корректно сбрасывают анимации. Кнопки не должны создавать повторную раздачу. Результат игры одинаков при включённых и выключенных анимациях.
2. **Проверка баланса.** Собрать статистику побед по seed и разным стратегиям, проверить полезность каждого улучшения. Сейчас перед двумя магазинами игрок получает по 5 монет, поэтому за забег можно купить не более трёх улучшений. Менять числа с измеримым обоснованием и обновлением документации.
3. **Звук и оформление.** Добавить звуки карт и срабатывания улучшений, улучшить читаемость текста. Для русского UI нужен шрифт с кириллицей и соответствующий диапазон символов; сохранить его лицензию.
4. **Контент и сдача.** После устойчивой базы добавить новые испытания, подготовить демо на 3–6 минут, официальный отчёт и слайды. Зафиксировать вклад участников и проверить чистую сборку на второй машине.

Скопируйте в новый чат расширения:

```text
Работаем в репозитории F1j1tun1/Final-Project-CGF.
Продолжаем Blackjack Forge — учебный C++17/OpenGL 3.3 Core проект.
Сначала прочитай AGENTS.md, README.md, docs/ARCHITECTURE.md и
docs/HANDOFF_VSCODE.md, затем осмотри код. Сохрани существующие
правила игры, детерминированность по seed и границы game/graphics/app.
Собери проект и запусти доступные тесты, сообщи фактический результат.

Следующая задача — анимация раздачи и переворота карт через события
презентации и стабильные идентификаторы карт. Держи таймеры, позиции
и повороты в слое представления. Закрытая карта дилера раскрывается
только после завершения хода игрока. Обработай restart, смену этапа,
изменение размера окна и отключение анимации. Не меняй исходы,
награды и порядок карт. Начни с небольшого работающего изменения,
проверь графику и обнови документацию по фактическому поведению.
```

Этот запрос передаёт цель следующего шага; архитектура и исходники остаются источником технического контекста.
