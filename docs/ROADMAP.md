# План реализации

Цель первого этапа — небольшой играбельный прототип: 3D-стол и карты, 2D-интерфейс, блэкджек, три испытания и магазин из четырёх улучшений. После его проверки команда продолжает работу в VS Code с CMake. Номера недель ниже относятся к требованиям курса, а не к рассчитанным календарным датам.

## 1. Основа и проверка правил

- Собрать проект из исходников через CMake на Windows.
- Проверить `evaluateHand()`, действия игрока, дилера и переходы между фазами через CTest.
- Пройти раздачу до результата, затем весь забег до победы или поражения.
- Убедиться, что повторное нажатие недоступного действия не меняет игру.

Готово, когда правила работают без графики, а приложение запускается по инструкции после чистой сборки.

## 2. Прототип для Week 5

- Показать стол, карты и фишки в 3D, HUD и управление в 2D.
- Продемонстрировать собственный цикл рендеринга и хотя бы одну интерактивную возможность, например «взять карту».
- Подготовить proposal: проблема, цели и предварительный стек.
- Получить шаблон отчёта и начать Introduction, Background, Project Description и Methodology.

Готово, когда команда может показать работающий прототип и объяснить, как действие меняет данные игры и сцену.

## 3. Бета для Week 7

- Проверить полный цикл: раздача → результат → следующий этап → магазин → финал.
- Проверить четыре улучшения отдельно и в сочетаниях.
- Проверить Blinn–Phong, текстуры, матрицы преобразований и корректные нормали.
- Проверить размер окна, читаемость интерфейса, ошибки шейдеров и освобождение ресурсов.
- Проверить сборку и запуск на второй машине с поддержкой OpenGL 3.3.
- Протестировать начальные цели 30/65/100, пять раздач и экономику магазина; корректировать по результатам игры.

Готово, когда все обязательные функции доступны и воспроизводимы, а оставшаяся работа относится к оформлению и исправлениям.

## 4. Финальная сдача

- Зафиксировать версию, которую команда действительно собирала и запускала.
- Завершить отчёт по шаблону курса: архитектура, графические техники, проверки, ограничения и вклад участников.
- Подготовить слайды и демо на 3–6 минут.
- Повторить сборку по README в чистой папке; передать исходники, зависимости, лицензии и инструкции.

Предлагаемый сценарий демо на пять минут:

| Время | Содержание |
| --- | --- |
| 0:00–0:30 | Идея и цель проекта |
| 0:30–2:00 | Раздача, решение взять карту или остановиться, итог |
| 2:00–3:00 | Улучшение, магазин и изменение стратегии |
| 3:00–4:15 | 3D-сцена, MVP, освещение, текстуры и 2D HUD |
| 4:15–5:00 | Проверки, результат, вклад команды и ограничения |

## Разделение работы

| Участник | Основная зона | Общая проверка |
| --- | --- | --- |
| A | Правила, состояния забега, улучшения, тесты | Прогон забега и проверка баланса |
| B | OpenGL, меши, камера, шейдеры, текстуры | Сборка на второй машине и визуальная проверка |
| C, если есть | UI, интеграция, документация, демо и слайды | Проверка соответствия заданию |

Если участников двое, UI и документацию делят между A и B. Перед слиянием изменений каждый объясняет другому свой модуль; оба должны уметь собрать проект и провести демо.

## После устойчивого прототипа

Запланированные расширения: анимация раздачи и переворота карты, звук, сохранение забега, новые улучшения и правила дилера, более выразительные материалы. Сначала закрываются требования курса и ошибки текущего цикла. Сетевой режим, физический движок и большое число режимов в первый объём не входят.

Для продолжения в VS Code открыть корень проекта, прочитать README, архитектуру и документ передачи проекта, выполнить сборку и тесты, затем выбрать одну задачу с ясным критерием готовности. История чата не должна быть единственным источником правил проекта.
